# 공개 데이터 전용 단계 모니터링

운영 서버는 계속 `server:app`을 사용합니다. 기본 observer는 None이며 요청 본문을 기록하지 않습니다.
`public_guard_monitor:app`은 별도 진단용 진입점입니다. 명시적 활성화와 공개 평가 폴더가 있어야 시작됩니다.
대회 공개 guard.jsonl의 대화·후보 답변과 정확하게 일치하는 요청만 기록하고 처리합니다.
공개 목록에 없는 요청은 모델 호출과 trace 생성 전에 거부합니다. 기존 인증도 유지합니다.

## 실행

프로젝트 루트에서 .env를 읽어 들인 뒤 실행합니다.

```sh
set -a
source .env
set +a
python evaluate_public_monitor.py
```

도구는 새 진단 HTTP 서버를 띄워 공개200개를 동시8요청으로 평가하고, 종료 시 자신이 띄운 서버만 종료합니다.
각 요청은 한 번의1차 판정만 생성하며 같은 요청의 검토·재판정·최종응답을 연결합니다.
별도로 분석하려면 출력된 평가 폴더를 아래 명령에 전달합니다.

```sh
python analyze_public_traces.py work/evaluations/public-monitor-실행시각
```

## 기록

- `traces/pub-ID--trace-ID.json`: 전체공개입력, 각GPT의 실제messages/스키마/출력/토큰/시간,
  검색질의와결과, 1차판정, 감독자선택이유, 재판정, 최종응답을 시간순으로 연결합니다.
- `items.csv`, `items.md`, `items.jsonl`: 전체200개 정답·1차·최종·오류변화·감독자조치와trace경로.
- `new-errors.json`, `fixed-errors.json`: 판정이 나빠지거나 좋아진 항목별 증거.
- `stage-summary.json`: 단계별호출·오류·조치·정확도·시간 집계.
- `source/`, `manifest.json`, `cleanup.json`: 소스해시/실행조건/진단서버종료상태.

API키, Authorization헤더, SDK객체, 예외본문은 기록하지 않습니다.
정답라벨은 모델입력에 넣지 않고 실행후공식채점함수로만 대조합니다.
관찰관계 자체의정확도는 라벨만으로확정하지않습니다. 인용과의미는 기록을보고확인해야합니다.
모니터링콜백실패는원래판정을바꾸지않고 monitor_errors로집계합니다.
진단모듈은 운영서버에서 import되지 않습니다. 관찰코드가 판정정책을 변경하지 않는지 회귀테스트합니다.

## 해석

기존HTTP오류의원인을복원하는것이아니라, 새실행에서동일요청의단계변화를추적합니다.
최종HTTP시간에는모니터링과저장오버헤드가포함됩니다. 1차시간은서버내부단계시간입니다.
공개개발셋 단일실행이므로 일반화나 반복안정성을입증하지않습니다.
