# 가드 검토 구조

서버 기본값은 `GUARD_REVIEW_MODE=off`입니다. `all`은 전체 검토,
`selective`는 후보 답변이 있거나 입력이 block 또는 normal 이외 범주일 때 검토합니다.

## 입력 검토 분리

1차 입력·근거·안전 판정은 기존 프롬프트와 병렬 실행을 그대로 사용합니다.
1차 판정 후 입력 검토와 출력 검토를 **병렬** 실행합니다.

- 입력 검토 함수: `review_input(client, model, messages, initial_input)`.
  JSON에는 `conversation`, `initial(decision/category)`만 있습니다.
  후보 답변·검색 자료·출력 판정은 인자로도 받지 않습니다.
  스키마도 입력 target, keep/revise, input_intent, conversation 인용만 허용합니다.
- 출력 검토: 후보 답변·대화·검색 자료·기존 output을 받습니다.
  grounding/safety만 수정하며 input 수정 권한은 없습니다.
- 감독자는 각각의 수정 범위를 다시 검사하고, 입력은 input 필드에만,
  출력은 output 필드에만 병합합니다. 인용 존재 검증은 의미적 정답 보장이 아닙니다.

각 검토 분기는 최대1회 복구합니다. 성공한 입력 검토를 출력 실패 때문에 다시 호출하지 않습니다.
출력 분기의 복구는 오류 재검토 또는 근거 부족 재검색+재검토 중 하나입니다.
후보가 있는 요청의 검토 호출은 최초2회, 최악4회입니다. 기존 통합검토는 최초1회/최악2회였습니다.
후보가 없으면 입력 검토만 호출하며 검색·출력 검토는 생략합니다.

전체28초, 기본단계20초, 검토호출당 최대12초를 남은 공통 마감 안에서 사용합니다.
검토 실패 시 해당 분기의 최초 판정을 보존합니다. 상대 분기의 성공한 수정은 유지합니다.
기본 판정 자체가 실패하면 기존처럼503입니다.
운영 로그는 오류 종류와 시도 횟수만 남기고 요청·응답·인용 본문을 저장하지 않습니다.

HTTP 부하 검사는 `python test_guard_load.py --url http://127.0.0.1:8000/guard --requests 64 --workers 64`입니다.

이번 수정 전후 비교는 저장된 공개200개1차 판정을 재사용하고, 공통 top5 근거를 각 버전에 전달합니다.

실제 HTTP/런박스/프록시 지연 측정과 혼동하지 마세요.
공개 오답별 하드코딩, 별도 모델, 신규 의존성은 추가하지 않았습니다.

## 출력 전용 계약

출력 호출은 OUTPUT_REVIEW_POLICY만 사용하고 반환 루트는 grounding, safety 두 필드입니다.
각 필드는 행동별 union으로 제한합니다. keep/insufficient에는 이유만, revise에는 해당 수정값과 인용만 받습니다.
안전성에는 insufficient를 허용하지 않습니다. grounded=true는 빈 구간, false는 하나 이상의 구간을 요구합니다.
검증 후 기존 ReviewReport로 변환하여 기존 감독자의 인용 검사와 수정 적용 정책을 유지합니다.
입력 검토, 1차 세 판정, 병렬 구조, 재시도 횟수, 타임아웃은 변경하지 않았습니다.
공개 문항 ID나 정답별 예외를 추가하지 않았습니다.

수정 전후 비교는 저장된 공개 출력86개와 동일한 1차 판정·근거를 사용하며,
입력 검토와 1차 GPT는 호출하지 않습니다. 출력 검토 지연만 실측합니다.
이 비교의 전체 지연 추정치는 입력 검토와 HTTP를 포함하지 않으므로 실제 서버 지연으로 해석할 수 없습니다.
