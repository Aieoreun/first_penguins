# 검토 3개 병렬 실행과 상태 기반 재판정

- 입력 검토: 대화와 기존 입력 판정만 전달합니다.
- 근거 검토: 대화, 후보 답변, 검색 자료, 기존 grounded/unsupported만 전달합니다.
- 안전성 검토: 대화, 후보 답변, 기존 safe만 전달합니다.
- 세 검토는 같은 1차 판정의 복사본을 받아 병렬 실행하며 서로의 결과를 보지 않습니다.

| 상태 | 감독자 조치 |
|---|---|
| supported | 기존 판정 유지 |
| refuted | 원문 구간과 인용 출처를 검사하고 해당 영역만 1회 재판정 |
| insufficient | 입력·안전성은 불확실성 기록 후 유지. 근거는 1회 재검색, 새 자료가 없으면 유지 |

검토 결과는 최종 판정값을 포함하지 않습니다. 재판정에 status/rule/reason/인용 또는 관찰/initial을 데이터로 전달합니다. 재판정 모델에는 검토 의견이 정답이 아니며, 반증이 성립하지 않거나 정보가 계속 부족하면 기존 판정을 유지하도록 지시합니다. 후보 답변을 고쳐 쓰지 않습니다.

초기 판정 실패의 기존 재시도 정책은 유지합니다. 새 검토는 영역별 1회, 재판정도 영역별 최대 1회이며 전체 28초 예산을 공유합니다. 검토 실패 또는 재판정 실패는 해당 초기 판정을 보존합니다. 런타임의 기본 검토 모드 설정은 변경하지 않았습니다.

## 평가 방법
공개 200개 이전 모니터링에서 저장한 같은 1차 판정과 검색 자료를 두 버전에 재사용합니다. 문항 ID와 정답 라벨은 모델 입력에 포함하지 않습니다. 수정 전후 검토와 재판정은 실제 API를 호출하며, 공식 로컬 채점 함수로 결과를 점수화합니다. 시간은 검토 시작부터 종료까지이고 HTTP 서버 전체 시간은 아닙니다. 코드·전체 입출력·감독자 조치·재판정·최종 결과를 함께 저장합니다.

이는 공개 개발 세트 단일 실행 비교입니다. 숨겨진 평가 성능이나 모델의 반복 실행 안정성을 입증하지 않습니다.
