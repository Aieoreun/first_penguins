## 1. 문제 정의 및 환경 제약 (`SPEC.md`)

- **엔드포인트**: `POST /tutor` (50%), `POST /guard` (50%), 모두 HTTP 200 단일 JSON 응답 (`redirect_slashes=False`, Bearer 토큰 인증).
- **실행 제약**: CPU 전용 엘리스 런박스(`C-8`, GPU 없음), 동시 요청 최대 **64개**, 요청당 **30초** 타임아웃, 전체 약 600문항 처리 시간 제한(약 5분 미만).
- **허용 범위 (`SPEC.md` §7.1)**:
  - API: `gpt-5-nano`, `text-embedding-3-small`만 허용.
  - 라이브러리·모델: `kiwipiepy`(한국어 형태소 분석기·사전), `bm25s`, `scikit-learn` 등 배포 자료/운영진 LLM 예시로 **처음부터 직접 학습**하는 모델 및 언어 처리 도구는 허용. 외부 사전학습 임베딩·리랭커·분류 모델 탑재 금지.
- **로그 규정 (`SPEC.md` §8)**: 요청 메시지·후보 답변·생성 답변 본문 저장/열람 절대 금지. 지연시간·길이·상태코드·오류명 등 비본문 메타데이터만 기록.

## 3. 주요 설계 결정

### 결정 1. 64 동시성 연결 풀링 및 서버 기동 시 사전 색인

- **결정**: `ClientPool`에서 `httpx.Limits(max_connections=100, max_keepalive_connections=64)`와 `asyncio.Semaphore(64)`를 공유하고, FastAPI `lifespan` 단계에서 `KBIndex`·`GuardClassifier`·`GuardVerifier`·`TutorPipeline`을 모두 초기화한다.
- **이유**: 첫 요청 시 색인/임베딩을 초기화하면 30초 타임아웃 위험이 있고, 동시 64요청에서 매번 커넥션을 새로 열면 소켓/핸드셰이크 병목이 발생한다.

### 결정 2. Stage-0 정규화 및 난독화 복원 (원문 스팬 비변형 원칙)

- **결정**: `app/normalize.py`에 NFKC 정규화, 제로폭 문자(`U+200B..U+206F`, `U+FEFF`) 제거, 1음절 한글 띄어쓰기 난독화 복원(`collapse_korean_obfuscation`)을 구현해 검색과 입력 분류 전처리에만 적용한다.
- **주의**: `GuardVerifier`의 `unsupported`는 `candidate_answer`의 **원문 그대로(verbatim substring)**를 반환해야 하므로 입력 정규화 함수로 후보 답변을 변형하지 않는다.

### 결정 3. 하이브리드 KB 색인 (Kiwi + BM25s + Optional Dense RRF)

- **결정**: 48개 `.md` 섹션과 23개 `-table1.csv` 표를 389개 자식 청크(표 행 자연어화 88개 포함)로 분할하고, 과목 고유 엔티티(`다람쥐은행`, `다람 문구점`, `kkumtle`, `HelpyCode` 등)를 `kiwipiepy` 사용자 사전에 등록한 뒤 `bm25s`와 `text-embedding-3-small` 코사인 유사도를 RRF(`k=60`)로 결합한다.
- **이유**: 학습자 질문이 과목/섹션명 대신 가상 은행·상품·실습명을 직접 언급하는 경우가 많아 어휘 매칭(BM25)과 의미 검색(Dense)의 결합이 유리하다.

### 결정 4. 입력 가드: CPU TF-IDF 폴백과 `gpt-5-nano` + 동적 kNN 분기

- **결정**: `GuardClassifier`는 `SPEC.md` §7.1에 맞춰 `TfidfVectorizer` + `LogisticRegression`을 `public/guard.jsonl`로부터 처음부터 학습하는 CPU 경로를 구현하되, 실제 `OPENAI_API_KEY`(`chat_client`)가 연결된 환경에서는 `low_signal_input` 규칙 외 입력을 `public/guard.jsonl` 동적 kNN 유사 예시 + `gpt-5-nano`로 직접 판정한다.
- **이유**: 200건 규모의 학습 데이터로 학습한 TF-IDF 분류기는 5-fold OOF 교차검증에서 `54.12`점에 그쳐(in-sample `81.03` 대비 큰 격차), 비공개 OOD 입력에서 과적합 위험이 크다고 판단했다. (자세한 수치는 `02_실험_결과.md` 참조)

### 결정 5. 후보 답변 검증 (`GuardVerifier`)의 `safe`/`grounded` 분리 및 스팬 스내핑

- **결정**: 프롬프트에서 `safe`와 `grounded`를 독립적으로 판정하도록 지시하고(`safe=false`여도 지어낸 사실이 없으면 `grounded=true`), 모델이 반환한 `unsupported` 구절을 `grader/scoring.py`와 동일한 정규화 인덱스 맵 + `difflib` 기반으로 `candidate_answer`의 정확한 원문 substring에 스내핑(`_snap_span_to_verbatim`)한다.

### 결정 6. 초기 Single-pass 선택과 향후 아키텍처 전환 방향

- **초기 선택**: 64 동시성 및 30초 제한 위험을 피하기 위해 초기 구현(`e0c65a1`)은 검색·사례 검색 후 단일 LLM 호출로 답하는 Single-pass 구조로 설계했다(자율 멀티에이전트 루프 보류).
- **재검토 (2026-11-15)**: 1차 런박스 제출에서 600문항 전체가 `67.980s`에 완료되어 시간 여유가 확인되었고, 멘토링 피드백(긴 응답시간 처리, `Supervisor` 패턴, `Search -> Review -> Write`, 출처의 명시, 하네스 엔지니어링)을 반영해 조건부 재검색·근거 인용 검증 노드를 포함한 `Supervisor` 구조로의 확장을 다음 단계로 설정했다.
