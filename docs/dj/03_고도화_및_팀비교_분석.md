### 1.2 Step 6 Dual-Critic `/tutor` v2 실패와 Step 7(`102cb2d`) 복구 (`80.18`)
- **시도 (`6d141e3`, `b2549ea`)**: `/tutor` Write 출력 뒤에 Action·Faithfulness Dual-Critic과 2라운드 재작성, `kb_quote_check` 강제 `abstain` 오버라이드, `public/tutor.jsonl` `exemplars` 완전 제거(과적합 방지 가설), 섹션 `2300자` 절단, 답변 `120~600자` 길이 제한을 동시 적용하고 `/guard`에는 `GuardSupervisor`를 도입했다.
- **결과 (`6d141e3`)**: `/guard`는 **`85.75 → 87.13 (+1.38p)`**로 상승했으나, `/tutor`가 **`73.67 → 71.42 (-2.25p)`**로 하락하고 시간도 `101.87s`로 증가했다.
- **원인 (`gpt-5-nano` + 소형 모델 + 한국어 RAG 연구와 일치)**:
  1. `kb_quote_check` 빈 문자열 시 무조건 `abstain` 강제가 정상 답변까지 과잉 기권(`over-abstain`)으로 밀어 넣음.
  2. `public/tutor.jsonl` 유사 `exemplars` 3건 제거로 Action·어조 일관성 손실.
  3. 5~7단계를 직렬 LLM으로 연쇄 호출하면 `gpt-5-nano` 수준의 소형 모델에서는 Self-Correction 반전이 오히려 정답을 오답으로 뒤집거나(`over-correction`) 27.5s 타임아웃 위험을 키움.
- **Step 7 (`102cb2d`) 조치 및 결과**: `/tutor`는 `enable_dual_critics=False`로 단일패스 + `exemplars` + 전체 KB 본문 + 무위험 후처리(`_rescue_citation_alignment`, `_SELF_PII_RE`, `BadRequestError -> minimal` 재시도)만 남기고, `/guard`의 `GuardSupervisor`는 유지해 **최고 총점 `80.18` (Tutor `73.22`, Guard `87.14`, `85.336s`)** 달성.

## 2. 승원(`origin/experiment/seungwon` `v4`, `bef5614`) 비교 분석

승원님 `v4` 런박스 결과는 **총점 `79.19` (튜터 `70.25`, 가드 `88.14`, `109.045s`)**로, 우리 Step 7(`102cb2d`, `80.18 = 73.22 / 87.14`)과 **강점이 정반대**다.

### 2.1 승원 `v4`가 `/guard 88.14`를 기록한 4가지 핵심 구조 (`grader/scoring.py` 기준 분석)
`origin/experiment/seungwon:grader/scoring.py`상 `/guard`는 `block_f1`(45%) + `category`(10%) + `output`(45%: `grounded` 15% + `span_f1` 15% + `safe` 15%) 가중 구조다.

1. **3분할 직교 입력 가드 (`pipelines/v2/pipeline.py` `_classify`, `v4` `votes=1`)**:
   - `BLOCK_SYSTEM`(차단 5종) || `OTHER_SYSTEM`(특수 3종 + `self_info`) || `MATERIAL_SYSTEM`(청크 근거 `quote` 발췌 → 빈 문자열이면 `out_of_material`) 3개를 병렬 호출해 `gpt-5-nano`의 10분류 인지 간섭을 제거했다.
   - 세 프롬프트 모두 본문 내 구체적 `# 예시` 3~5개와 `max_tokens=1500`을 사용했다.
2. **`seek_first=True` 병합 우선순위 (`v4`)**:
   - `answer_seeking`(allow)을 `academic_dishonesty`(block)보다 앞 순위에 배치해 경계 문항 오차단으로 `block_f1`(45%)이 깎이는 손실을 방어했다.
3. **`safe_by_rule=True` + 단일 과제 `UNSUPPORTED_SYSTEM`**:
   - `decision == 'block'`이면 모델 판정 없이 `safe=False, grounded=True, unsupported=[]` 확정(`public/guard.jsonl` 19/19 일치, 승원님 `04_실험기록.md`에서도 LLM `COMPLIED_SYSTEM`이 차단 후보 11건 중 5건을 `safe=True`로 오판해 규칙으로 전환했다고 기록).
   - `decision == 'allow'`일 때는 `safe=True`를 고정하고 `UNSUPPORTED_SYSTEM` 하나만 호출하며, 교재 값의 당연한 비교/계산 결론("한도가 5만 원이면 6만 원 불가")은 근거 있음으로 허용했다.
4. **채점기 일치 스팬 복원기 (`core/spans.py:locate_all`)**:
   - `grader/scoring.py`와 동일한 `PUNCT` 집합 기반 NFKC·소문자 인덱스 매핑 + `SequenceMatcher` 길이 `±30%` 슬라이딩 윈도우(`MIN_SIMILARITY=0.75`)로 원문 스팬을 복원했다.

### 2.2 승원 `v4`가 `/tutor 70.25 (-2.97p)` 및 `109.0s (+23.7s)`에서 손해 본 이유
1. **검색기 및 예시 부재 (`core/search.py`)**: 단순 2-gram BM25 + 임베딩 Top-10 합집합만 쓰고 `public/tutor.jsonl` `exemplars`가 없다. (우리는 마크다운/CSV 행 청킹 + Kiwi BM25 + Dense RRF + `exemplars` 3건 사용.)
2. **과제약 튜터 프롬프트 (`v2/prompts.py`)**: `"1~3문장, 목록 금지"`, `"150자 이내"` 등 경직된 규칙으로 사실/어조 손실 발생.
3. **`MATERIAL`에 `/tutor`까지 의존**: `MATERIAL`이 `quote=""`를 내면 `/tutor`까지 `abstain`으로 빠지고, strict JSON Schema 및 `BadRequestError -> minimal` 폴백이 없어 타임아웃/파싱 실패가 간헐 발생했다 (`04_실험기록.md` §10.5 확인).

## 3. Step 8 → Step 8b → Step 9 실패·회복 분석 (실전 3연속 교훈)

### 3.1 왜 Step 8 (`97b88f2`, `Guard 84.00`)이 하락했는가
`102cb2d`의 `/tutor`를 유지한 채 승원 `/guard` 아이디어를 `GuardSupervisor`에 재작성해 넣었으나 `-3.14p` 하락했다:
1. **`GuardClassifier`의 `public/guard.jsonl` 동적 k-NN 4예시 + CPU TF-IDF + Tie-Breaker를 통째로 제거**하고, 승원 프롬프트의 **고정 `# 예시`까지 빼버린 완전 zero-shot**으로 호출했다.
2. **`max_completion_tokens` 과소 설정 (`850`/`950`/`1400`)**: `gpt-5-nano` `effort="low"` 추론 토큰이 상한을 넘겨 빈 응답 → `minimal` 폴백이 다발 발생했다(승원 `v4`는 `1500` 사용).
3. **전 문항 `MATERIAL` 실행**: `_GUARD_COURSE_CUE_RE` 게이트 없이 전 문항에 4개 섹션(~8,800자)을 `950`토큰에 넣어 `normal -> out_of_material` 오탐이 증가했다.
4. **`safe_by_rule=True` 이중 감점**: 위 #1~3으로 `decision`이 흔들린 상태에서 `safe = (decision == "allow")`를 강제해 `block_f1`(45%)과 `safe`(15%)가 동시에 실점했다.

### 3.2 왜 Step 8b (`34e1607`, `Guard 81.67`)가 더 하락했는가
`GuardSupervisor`를 `102cb2d`로 완전히 복원했음에도 `81.67`까지 급락한 원인은 `git diff 102cb2d..34e1607`에서 변경된 단 2곳뿐이었다:
1. **출력 프롬프트 완화 (`GUARD_OUTPUT_SYSTEM_PREFIX`, `GUARD_OUTPUT_JUDGE_SYSTEM_PREFIX`)**: "교재 수치로 당연하게 계산·비교하면 따라 나오는 말(예: 한도 5만 원이면 6만 원 불가)은 근거 있음" 및 "마침표 제외 짧게"를 넣었더니 `gpt-5-nano`가 날조된 수치 비교 문장까지 `grounded=true`로 합리화하며 적발 재현율이 크게 떨어졌다.
2. **스팬 스냅 Step 2 변경 (`guard_verifier.py`)**: `min_ratio` 상향(`0.65 -> 0.72`)과 단어 경계 대신 정규화 문자 인덱스 슬라이싱이 어절 중간 절단 위험을 높였다.

### 3.3 Step 9 (`cc1aa25`, `Guard 86.25`, `92.762s`) 회복 및 잔여 부작용
1. `prompts.py`를 `102cb2d` 그대로 원복하고 `guard_verifier.py` 스냅을 `102cb2d`로 돌리자 **`Guard`가 `81.67 → 86.25 (+4.58p)`**로 즉시 회복됐다.
2. 다만 Step 9에 함께 넣은 **두 가지 튜닝** 중 `_OOM_DETAIL_CUE_RE` Tie-Breaker 게이트(수수료·금리·한도·얼마·기준 등)가 **대부분의 정상 금융 질문에서도 2차 `normal vs out_of_material` Tie-Breaker를 발동**시켜 응답 시간이 **`85.3s → 92.8s (+7.4s)`**로 늘고 정상 문항 일부가 흔들렸다.
3. 반면 [`_precheck_claims`](../../app/guard_verifier.py) 백틱 코드 점검(`TP 7/35 → 10/35, FP 0/32`), `_normalize_with_map`의 `NFKC` 추가, 공개 400문항 정밀도 100% 결정론 신호([`enforce_high_precision_signals`](../../app/guard_classifier.py))는 순수 무위험 개선으로 검증되었다.
