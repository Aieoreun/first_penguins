## 4. 1차 제출 및 코드 정적 분석으로 확인된 문제점

1. **`/tutor` 내 입력 가드 Dead Code (`app/tutor_pipeline.py:137-144`)**
   - `TutorPipeline._run_guard`가 `("classify_input", "predict_input", "check_input", "predict")` 메서드를 탐색하나, 실제 `GuardClassifier`의 메서드명은 `classify`다.
   - 이로 인해 1차 제출 당시 `/tutor`의 사전 가드 분류 호출이 항상 `(None, 0.0)`을 반환하며 사실상 비활성화되어 있었다.
2. **`/guard` 출력 검증의 `grounded` 강제 `True` 덮어쓰기 (`app/guard_verifier.py:259-264`)**
   - LLM이 `raw_grounded=False`로 판정했더라도 `_snap_span_to_verbatim`으로 스내핑된 `unsupported` 목록이 비어 있으면 `elif not raw_grounded: grounded = True` 분기에 의해 `grounded=True`로 덮어써지는 버그가 존재한다.
3. **지연시간 여유 확인 (Latency Headroom)**
   - 600문항 전체 처리 시간이 `67.980s`로 전체 제한(~300초) 대비 여유가 충분하므로, 추가 검증(Review) 및 조건부 재검색 단계를 도입해도 타임아웃 위험을 통제할 수 있음을 확인했다.
