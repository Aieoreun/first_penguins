# 입력 분류기 2×2 비교 — 2026-11-18

사용자가 네 조합의 실험과 실제 제출 단계 준비를 새로 요청했다. 이전 라운드의 중단 기록은 유지하며 이번 유한 비교를 재개한다. 기존 `experiment/kimjaehak-peace-guard-fusion`에서 별도 variant만 추가한다. 기존 material_budget·fast_cancel·fast_gate90와 기본 서버는 보존한다.

## 비교 설계

|variant|입력 특징|분류기|
|---|---|---|
|jh_cm_char_lr|문자 TF-IDF, 2~5gram, min_df2, 최대60,000|로지스틱 회귀 C3000|
|jh_cm_dense_lr|제공 text-embedding-3-small 1536차원|로지스틱 회귀 C3000|

|jh_cm_dense_mlp|위와 완전히 같은 제공 임베딩|위와 같은 신경망|

공개 tutor+guard 400개로 처음부터 학습한다. class_weight 또는 sample_weight로 클래스 균형을 동일하게 처리한다. 임베딩은 기존 제공 API로 생성하고 출처·ID·해시를 검증한 자산을 float64로 읽어 동일하게 L2 정규화한다. 외부 모델이나 새 데이터셋을 학습하지 않는다.

기존과 같은 문자 유사도 .82 그룹, seed20261116의5-fold를 동결한다. 각 TF-IDF 어휘와 분류기는 학습 fold로만 적합한다. 신경망 초기값은20261118/19/20이며 첫 seed를 배포 비교에 사용한다(최고 seed 선별 안 함). 공개자료는 이전 개발에 노출돼 있어 독립 holdout이 아니다.

먼저 단독 정확도·macro F1·차단 F1·오차단/미차단을 비교한다. 신뢰도 높은 비유해 예측에서 전체400개 대비10/25/50/75%를 직접 처리하는 동일 coverage를 비교한다. 이는 OOF 순위 진단이며 실제 확률 보정이나 비공개 정확도 보장이 아니다. 실제 서버는 OOF 상위25%(100개)의 최저 확률을 각 모델의 초기 임계값으로 정해 비교한다. OOF 정답을 최대화하는 임계값 탐색은 하지 않는다. 전체400개 재학습과 새 질문에서는 실제 처리 비율이 달라질 수 있다.

## 서버 변경 범위

`fast_cancel`의 `/guard` 입력 분류기만 교체한다. 새 분류기가 확신하지 못하면 기존 category 모델을 또 통과하지 않고 공통 LLM 입력 판정으로 보낸다. 유해 요청/발언 구분은 기존 공통 subtype 모델의 .95 기준을 유지한다. 따라서 단순 문자+LR 대조군도 기존 fast_cancel의 C3000→C1000 보조 게이트 연쇄와 완전히 같지는 않다. 기존 fast_cancel을 다섯 번째 실제 운영 기준선으로 별도 측정한다.

튜터·교재 검색·출력 grounding·안전성·28초 제한·비스트리밍은 유지한다. Dense 두 후보는 마지막 사용자 발화만 추가 임베딩하며, 대화 전체/후보 답변을 넣은 검색용 벡터와 혼용하지 않는다. 추가 호출은3초 이내, 제공 API 장애·모델 불일치·벡터 오류는 공통 LLM으로 복구한다. 새 요청 내용/벡터/예측을 저장하지 않는다. 모델은 서버 준비 시 공개자료로 학습한다.

## 이번 라운드 판단과 제출 순서

1. **첫 제출 시험: `jh_cm_dense_lr50`.** primary196과 혼합388에서 상승했다. 같은 임베딩을 쓴 신경망보다 우선한다. 다만 alternative184에서는 기존보다 낮았다.
2. **신경망 비교용: `jh_cm_char_mlp50`.** 네 조합을 직접 비교하려는 사용자 요청에 따라 남긴다. 현재 로컬 증거만으로는 기존보다 좋다고 추천하지 않는다.
3. 문자 LR50·임베딩 MLP25/50도 실행 가능하며 기존 후보는 모두 보존한다. 임베딩 MLP는 수렴 경고가 남은 fold가 있고 성능상 이점도 없어 우선순위가 낮다. 작은 신경망 한 구조의 결과이며 모든 신경망이 불리하다는 결론은 아니다.

현재 최종 제출 후보를 자동 교체하지 않는다. 새 후보의 실제 제출 결과를 받은 뒤 variant·전체/튜터/가드·Duration·seed를 함께 기록하고 판단한다. 새 후보가 떨어지면 기존 최종 후보로 돌아갈 수 있다. 계정별 마지막 제출이 집계되므로 비교 완료 후 최종 선택한 서버로 다시 제출한다(SPEC.md).
