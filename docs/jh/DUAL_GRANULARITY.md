# R5: 짧은·긴 청크 임베딩과 출처 후보 수 비교

2026-11-17 사용자 요청으로 시작한 별도 범위의 실험이다. R4 잔여40% 종료 기록은 보존한다.
기존 최종 후보 `jh_r4_material_budget`와 백업 `jh_r3_selected_focused`의 코드는 수정하지 않는다.
현재 공식 제출 추천도 그대로 유지한다. 이 문서의 개발 진단 점수는 비공개 제출 점수가 아니다.

## 비교 설계 — 결과 확인 전 고정

| 후보 | 검색 | 출처 LLM 후보 수 |
|---|---|---|
| 기준선 `jh_r4_material_budget` | 기존 BM25 + 긴 임베딩 | 기존 순서의 최대6섹션 |
| `jh_r5_dual6` | BM25 + 긴 임베딩 + 짧은 임베딩 | 새 공통 순서의 최대6섹션 |
| `jh_r5_dual_all` | 위와 동일 | 검색된 섹션 전체 |

두 신규 후보는 `material_budget`를 상속한다. 입력 판정 근거는 기존 BM25+긴 임베딩 그대로다.
짧은 임베딩은 이후 정상/PII 튜터의 출처 선택 후보만 보완한다. 확신도가 높은 기존 출처 게이트는
유지하므로 모든 요청이 출처 LLM을 호출하는 것은 아니다. 가드는 부모 검색 경로 그대로 사용한다.
평가기·core·기본 server·SPEC·public·kb 원본은 변경하지 않는다. 스트리밍은 사용하지 않는다.

### 청크와 후보 구성

- 긴 색인: 기존 `##` 단위 219개 유지. 글자 수 평균473.8, 중앙454, 최대2095.
- 짧은 색인: 608개. 본문 목표220자(소프트 기준), 제목 포함 평균196.8, 중앙198.5, 최대467.
  빈 줄 문단을 묶되 Q/A 한 쌍·코드 블록·표는 자르지 않는다. 제목과 부모 section ID를 유지한다.
- 모델은 `.env`의 제공 임베딩 모델을 그대로 사용한다. 별도 모델/차원 축소를 추가하지 않는다.
- 질문 임베딩은 기존 전체 대화 질의의 앞6000자로 한 번 호출해 두 색인에서 공유한다.
- BM25 상위10청크, 긴 임베딩 상위10청크, 짧은 임베딩 상위10청크를 각각 섹션 단위 중복 제거한다.
- 기존 판정 섹션과 마지막 질문 BM25 1위 섹션을 앞에 둔 뒤, 세 검색의 섹션 순위를 번갈아 합친다.
  동일 섹션은 한 자리만 차지한다. 기존 검색 섹션도 누락되지 않게 마지막에 합친다.
- 이 공통 목록의 앞6개 또는 전체를 LLM에 제공한다. 전체48섹션을 무조건 보내는 방식이 아니다.
- LLM에는 후보 섹션의 원문 전체를 제공한다. 선택 뒤 기존 focused 문단 재정렬로 답변한다.
- 신규 후보끼리는 마지막6개 제한만 다르다. 기준선 대비 변화에는 짧은 검색 추가와 순서 변경이
  함께 있으므로 둘의 효과를 개별적으로 분리했다고 주장하지 않는다.

### 색인과 실패 동작

`experiments/jh_server.py`가 신규 후보에 한해 서버 실행 전에 짧은 색인을 준비한다.
기본 캐시는 `index/jh_short_embeddings.json`이며 `JH_SHORT_INDEX`로 경로를 바꿀 수 있다.
원문+모델 키로 캐시를 검증하고 원자적으로 교체한다. 새 후보 시작 시 두 색인의 벡터 차원을 확인한다.
설정/색인 누락은 시작 단계에서 실패시켜 임베딩 없이 실행한 결과를 이 실험으로 오인하지 않게 한다.
요청 중 임베딩 실패는 기존 BM25 대체 동작을 따른다. 추가 임베딩 재시도는 없다.
색인과 `.env`는 커밋하지 않는다. 첫 구축 시간은 요청 처리 시간과 분리한다.

## 평가 순서

workers64, request-slots64, embedding-mode env, judge-workers32를 고정한다.
동시에 다른 후보/API 채점 작업을 돌리지 않는다. 수집을 먼저 완료하고 주최측 원본 채점기로 순차 채점한다.

1. 기존 공개 파생 primary tutor192개: 기준선 → dual6 → dual_all.
2. 교재 근거로 검토한 주제 전환 tutor114개: dual_all → dual6 → 기준선.
3. 결과가 모순되거나 작은 차이이면 해당 자료를 역순 반복해 변동을 확인한다.

원본과 파생 데이터는 이미 개발에 사용한 자료다. 독립 비공개 평가로 해석하지 않는다.
기록: 튜터 점수, 수집 총시간, 요청 p50/p95, HTTP/규격/채점 오류, 내부 단계 실패.
각 실행 manifest의 커밋·설정·원본 평가기 해시·데이터 해시를 보관한다.
필요하면 검색 단계만 별도 분석하되 공개 개발 데이터로 한정하고 정답은 런타임에 전달하지 않는다.
