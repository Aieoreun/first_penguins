# R7 — A 기준선 이후 개선 실험 (2026-11-20)

사용자 요청: 새 가설을 반복 검증하여 제출 점수를 개선한다. 계정 사용량 **40% 잔여**에서 새 실험을 중단하고 진행 중 채점·코드·결과·인수인계를 정리한다. 시작 시 사용44%/잔여56%를 도구로 확인했다. 이 작업은 같은 브랜치 `experiment/kimjaehak-peace-guard-fusion`에서 별도 variant로 수행한다.

기준선 A `jh_cm_char_mlp50`는 실제5회 평균84.640/튜터80.832/가드88.446, C는83.774/79.834/87.712였다. A5/C5는 사용자 실행명이 생략되어 직전 안내 순서로 대응했다. 실제 비공개 본문은 보지 않으며 이 집계로 특정 오류 유형을 추정하지 않는다. 공개 개발 자료의 실패를 별도로 분석한다.

## 고정 원칙

- A/C·기존 후보 보존. evaluator/core/server/SPEC/KB/public 수정 없음.
- 기존 제공 모델·환경변수 사용. 비스트리밍, 출력 한도2000 이하, 요청 전체 예산 유지.
- 공개 원본/기존 승인된 파생 개발 자료만 사용. 자료 계통과 학습 노출을 명시한다. 독립 holdout이나 실제 점수 추정으로 표현하지 않는다.
- 후보 수집과 judge는 순차 실행. 다른 후보 API 부하와 겹치지 않는다. 전체 점수와 변경 대상 지표를 따로 본다.
- 개선 후보는 다른 표현·반복·혼합 부하로 재검증한다. 실패와 잘못된 설정도 기록한다.
- 잔여율을 라운드마다 확인한다. 40% 이하이면 새 실험을 시작하지 않는다.

## 1차 가설 — 튜터 정책 경계와 생성

이전 A 공개 파생192에서 튜터96.09. 일부 실패는 단순 학습 걱정을 심한 고통으로 분류하거나, 학습 유도 응답에서 최종 계산값까지 제공한 사례였다. 검색의 실패와 분류/생성의 실패를 혼동하지 않도록 단계별로 나눈다. 기존 R6의 product_context는 구현만 되고 아직 API 비교하지 않았던 가설이다.

|A|jh_cm_char_mlp50|그대로|

가드는 A 그대로다. 신경망/LR 임계값·검색·토큰·시간 제한·추론 low는 바꾸지 않는다. 실제로 바뀐 tutor 요청 수를 debug boolean으로만 집계한다. 요청/응답 본문을 배포 서버에 기록하지 않는다.

첫 실행 `r7_t01`: 공개 파생192, A→other→scaffold→product, HTTP/서버64, judge32. 입력 원본·파생 라벨·코드 해시를 기존 runner로 동결한다. 결과 대기.
