# 튜터와 가드 분리 실험

2026-11-16 KST. 브랜치 `experiment/kimjaehak`, 시작 커밋 `51c97ac`.
사용자 요청: tutor에는 dense10, guard에는 기존 contextfast를 적용하고 기존 후보와 비교한다.
계정 잔여 사용량 시작 확인 92%. 잔여 50%에 도달하면 새 실험을 멈추고 진행 중 결과·검증·인수인계를 정리한다.

## 출발점과 가설

사용자 보고 실제 제출은 기존 contextfast + env가 83.22(tutor 76.75, guard 89.69),
dense10 안내 후 결과가 82.28(tutor 78.33, guard 86.24)였다.
서로 다른 표본이므로 두 결과의 좋은 부분을 합쳐 점수를 예상하지 않는다.
가설은 새 입력 예시/문맥 제한의 tutor 이득을 유지하면서 guard 경로의 변경을 제거하는 것이다.

## 구현과 비교 조건

- `jh_r2_tutor_split`: /tutor는 DenseTen 인스턴스, /guard는 상속한 ContextFast 경로 그대로.
- candidate_answer 유무로 경로를 고르지 않는다. 평가인지 감지하는 분기는 없다.
- 두 인스턴스가 요청 semaphore 하나를 공유하여 합산 동시성이 64를 넘지 않는다.
- 모델과 설정을 요청마다 바꾸지 않으며 요청/답변 본문은 저장하지 않는다.
- launcher가 엔드포인트별 variant와 tutor 설정 차이를 manifest용 시작 로그에 기록한다.
- 기준선과 후보 모두 embedding env, HTTP/내부 64, judge 32. 주최측 평가기·공개 자료·교재는 그대로다.
- 공개 원본 400과 기존 발화 변형 388 전체를 비교하고 순서를 뒤집어 반복한다.
- 전자는 공개 라벨 학습 내 점수이고 후자는 공개 부모의 약한 라벨을 상속한 개발 진단이다.
- 응답 수집과 판정 호출은 분리한다. 실패·퇴보도 보존하며 같은 응답을 좋은 점수가 나올 때까지 다시 채점하지 않는다.

## 후속 판단 기준

전체 반복 결과, tutor의 사실/인용/충실도/부적절한 수행, guard 세부 지표와 지연을 함께 본다.
guard 코드는 같아도 모델·부하 변동으로 결과가 달라질 수 있어 동일 점수를 보장하지 않는다.
분리 후보가 약하면 입력 예시와 문맥 제한을 분리하거나 tutor 답변 생성만 바꾸는 후속 가설을 검증한다.
실제 비공개 제출은 사용자가 실행하며 로컬 점수를 실제 점수로 보고하지 않는다.
