## 2차 후보: guided

구현 `4cc96c9`, 테스트 85개 통과. Peace 원본과 첫 네 비교군은 수정하지 않았다.

- `jh_guided_input`: Peace의 의도 경계를 정리한 단일 분류 호출에 상위 3개 교재 섹션을 제공한다. 유해 요청/발언 구분, 명시적인 정답만 요구, 마지막 발화의 무의미 입력, 자료 범위를 함께 판단하고 제공된 섹션 중 근거를 고른다. 답변 생성과 출력 검사는 v2 그대로다.
- `jh_guided_output`: v2 입력 + 독립 안전성 검사 + 짧은 원문 오류 구절 추출. 차단 입력은 v2처럼 근거 검사를 생략한다. 허용 입력에서는 근거와 안전성을 따로 검사하고 성공한 결과를 보존한다. 수업 무관 대행·숨은 지시 공개 주장·모욕·제출물 대행을 안전성 기준에 명시한다.
- `jh_guided_both`: 위 둘의 조합. 아직 점수가 검증되지 않은 후보이며 기본 배포 선택을 바꾸지 않는다.

첫 guided 입력 진단(`jh_guided_input_guard`, 코드 `189b9ca`)은 200건 모두 API 400으로 실패했다. 제공 프록시가 비스트리밍 응답의 `max_completion_tokens`를 2000 이하로 제한하는데 새 후보가 2400을 요청한 것이 원인이다. fallback만 평가된 가드 30.69는 모델 품질 비교에서 제외하되 실패 기록은 보존한다. `b1778b8`에서 2000으로 수정하고 제한 회귀 테스트를 추가했다. 원본 평가기의 스트리밍 4000 설정은 바꾸지 않았다. 새 후보는 실제 API smoke를 먼저 통과한 뒤 전체 진단한다.

입력 후보는 교재 밖 질문과 무의미 입력을 일부 회복했지만 제출 대행·유해 요청 누락이 늘어 채택하지 않는다. 출력 후보는 근거·구절·안전 지표가 모두 개선됐다. 다만 같은 v2 입력도 block F1이 0.8571→0.8926으로 변했으므로 가드 +4.25 전체를 출력 변경 효과로 단정하지 않는다.

추가 입력 배치 실험 `jh_guided_focus` (`bccdbe6`): 교재를 먼저 두고 대화와 마지막 발화를 뒤에 명시한다. 같은 분류 프롬프트·출력 검사로 자료가 요청 의도를 가리는지 측정한다.

`jh_guided_focus_guard` 결과는 가드 82.42, HTTP·형식 오류 0, 내부 category 오류 1 / timeout 1, 수집 73.24초다. 입력 배치 변경으로 80.27→82.42가 됐지만 v2 기준선을 넘지 못해 전체 평가 후보로 바로 올리지 않는다.

검색 후보만 오프라인으로 비교했을 때, 정답 근거가 있는 tutor 119건의 top1 적중은 기존 조각 BM25 108, 섹션 전체 BM25 106, 마지막 발화만 섹션 검색 93, 두 순위 결합 107이었다. 단순 검색 교체는 채택하지 않는다.

## 후속 검증 순서

네 비교군 완료 후 입력·출력 개선안을 `--endpoints guard`로 먼저 진단한다. 이때 출력되는 total은 전체 400문항 총점으로 해석하지 않는다. 유망한 조합은 전체 공개 평가, 원래 v4와의 비교, 반복 실행, 동시 64요청 점검으로 확인한다. 작은 단일 실행 차이만으로 우승 버전을 확정하지 않는다.

## 중단 복구

`971e15a`부터 공개 채점 호출의 입력 해시와 판정 결과를 실행 폴더의 `judge.jsonl`에 저장한다. 프롬프트·모델 호출 인자를 바꾸지 않는다. 같은 실행의 같은 채점 입력에만 결과를 재사용한다. 완료된 평가를 좋은 점수가 나올 때까지 다시 뽑는 기능이 아니다.

응답 400건 수집 이후 채점이 중단됐으면 다음처럼 재개한다.

```bash
.venv/bin/python experiments/jh_resume_score.py experiments/.cache/jh_RUN/VARIANT_1
```

평가기 해시·모델·공개 ID·문항 수가 맞아야 재개하며, 이미 완성된 결과는 덮어쓰지 않는다. 재개는 실행별 `result.json`을 만들며 상위 `summary.json`을 재작성하지 않는다.
