## 출력 구성요소의 통제 비교

같은 v2/v4 입력 경로도 실행별 차단 F1이 달라져 출력의 효과를 분리하기 어렵다. `jh_output_replay.py`는 `jh_full_v4/v4_1`의 **자체 입력 예측**을 고정하고, 공개 대화와 BM25 top1 검색을 재현하여 후보의 출력 검사만 호출한다. 예측 category/decision이 보존되는지 검사한다. 정답 입력 라벨은 상태 생성에 쓰지 않는다. 이 값은 출력 진단이며 전체 HTTP 평가나 비공개 점수로 취급하지 않는다.

```bash
.venv/bin/python experiments/jh_output_replay.py --source experiments/.cache/jh_full_v4/v4_1 --variant jh_v4_safety --name safety_fixed_1 --workers 16
```

고정 입력 출력 진단 1회: 원래 v4 87.79, `jh_v4_safety` 88.29. 두 실행 모두 입력 F1 0.8696 / 범주 정확도 0.8721로 동일하다. 그러나 같은 근거 알고리즘도 grounded 0.9070→0.9186, span 0.7787→0.8122로 흔들렸고, 안전성은 0.9767→0.9651로 낮아졌다. 0.50점 상승을 안전 검사 개선으로 해석하지 않는다. 원래 end-to-end v4의 89.17과도 출력 재실행 변동이 있으므로 작은 차이는 반복 확인한다.

## 자체 분류기 탐색 — 미채택

## 17차: 공개 출력 구절로 처음부터 학습한 경계 보정

SPEC §7.1이 허용하는 공개 라벨 기반 자체 학습으로, 후보 답변 86건의 unsupported 39구절을 문자별 0/1 라벨로 변환했다. 문항 ID나 질문→답 표를 저장하지 않는다. 현재 문자, 주변 문자·낱말, 단어 처음·끝 같은 로컬 특징을 DictVectorizer와 LogisticRegression으로 학습하며 외부 가중치는 없다. 학습은 서버 준비 단계에서 끝난다.

후보 답변 유사도 0.75로 묶기를 시도했으나 실제 합쳐진 쌍은 없어 86건이 각각 한 그룹이었다. 이 5-fold 검증에서 단독 span F1은 C=100에서 **0.4122**로 낮았다. 반면 학습 내 span F1은 1.0이었다. 신뢰도만으로 기존 판정을 교체하면 기준 0.95의 OOF F1도 0.8644→0.8335로 나빠졌다. **이 단독 교체는 채택하지 않는다.**

`59cfd7f`의 `jh_learned_output`은 C=100 / 모든 문자 최소 신뢰도 0.95를 요구하고, LLM이 이미 지목한 오류와 위치가 겹칠 때만 구절 경계를 보정한다. grounded·safe·입력 판정은 유지한다. OOF에서는 적용 0건으로 기존 0.8644 그대로, 학습 내 적용 33건으로 0.9700이었다. 이는 새 문항 개선의 증거가 아니라 명확한 공개 학습 내 개선이다. 기존 공개 파생 진단은 후보 답변 문자열을 그대로 썼으므로 이 추출기의 미관측 출력 검증으로 사용할 수 없다.

기본은 반복 최고 context_policy를 바탕으로 한다. `jh_learned_output5`는 다섯 번 출력 합의도 결합한다. 각각 전체 두 번 수집 중이며 판정기·원본 데이터는 그대로다. CPU 단일 추론 측정은 100자 0.0011초 / 1,000자 0.0075초 / 4,000자 0.0306초였다. 시간 보장은 아니며 실제 HTTP 동시성 결과를 별도로 확인한다. 테스트 161개 통과. 상세 OOF·학습 내 수치와 입력 해시는 `span_cv.json`에 보존한다.
