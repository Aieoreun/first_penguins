# 튜터 MLP 확장 실행 기록 — 2026-11-19

사용자가 계획 실행을 승인했다. 기준선은 실제85.41을 관측한 `jh_cm_char_mlp50`이며 가드는 모든 후보에서 고정한다. 기존 후보를 덮어쓰지 않는다. 구현 커밋 `5ab94e7`.

## 구현과 계획 조정

- A `jh_cm_char_mlp50`: 기존 튜터 LR/LLM 경로.
- B `jh_tm_selective`: 단일 턴의 정책 범주에 MLP 임계값0.9560244784 적용. 불확실하면 기존 튜터 경로.
- C `jh_tm_replace`: 정책 범주에 MLP 임계값0.7950809537 적용. 불확실하면 기존 범주 LR를 다시 통과하지 않고 문맥을 포함한 공통 LLM 판정.
- normal / out_of_material / harmful_content / low_signal_input은 기존 판정으로 넘긴다. 교재 범위와 유해 요청/발언 세부 판정은 그대로다. 저정보 규칙도 유지한다.
- 두 섹션 후처리를 이름 있는 함수로 분리해, 새 MLP 또는 공통 LLM 경로 뒤에도 기존 순서대로 정확히 한 번 호출한다. 이전 클래스는 같은 코드를 같은 순서로 호출한다. 검색·답변·가드 프롬프트·평가기 변경 없음.

사전 진단에서 공개 튜터200개 중 단일 턴이15개였다. OOF에서 단일 턴의 정책 범주 예측은2개뿐이므로 이 작은 부분으로 별도 임계값을 최적화하지 않았다. 튜터 전체 턴의 정책 예측50개 중 상위25%(13개)와50%(25개)의 최저 신뢰도를 사용했다. 두 구간 범주 오류0은 개발 OOF 진단이며 보정 확률/독립 검증 정확도가 아니다. 원본 그룹 분할과 학습자료 해시를 검증해 기존 OOF 예측을 재사용했다(API0). 상세 [OOF 집계](tutor_mlp_oof.json).

실제 첫 비교 문항192개에서 B의 잠재 대상은4개(임계값 .95 이상3개), 모든 턴의 정책 예측은57개였다. 이 때문에 C는 기존 LR와 같은 마지막 발화 입력을 사용해 다중 턴까지 적용하도록 계획을 조정했다. 문맥 손실 위험은 다중 턴 지표로 별도 점검한다. B는 계획대로 단일 턴에만 적용한다. B/C는 임계값·적용 범위·기권 경로가 함께 다르므로 운영 경로 비교이며 순수 신경망 종류의 대조가 아니다.

전체836테스트 통과. 최초 하네스 검사 실패1개는 새 endpoint 메타데이터 집계에 맞지 않는 테스트 fixture의 누락 필드를 보완한 뒤 통과했다. 새 테스트는 가드 위임, 동시 요청 모델/임계값 불변, 신경망 채택/기권, 다중 턴 경계, 모델 오류 복구, 출처 후처리 순서와 기존 생성 경로를 확인한다.

## 실행 방식

기존 승인된 공개 파생 자료 `jh_augment_public2_1/paraphrases.jsonl`만 사용한다. 학습에는 넣지 않았으나 이전 개발에 쓰인 원문에서 파생된 자료이고 라벨 잡음이 있어 독립 holdout은 아니다. 원본 채점기와 프롬프트를 그대로 사용한다. 후보별 수집은 순차로 끝내고 그 뒤 순차 채점해 평가 호출과 서버 부하를 겹치지 않는다. 환경은 주최측 변수 우선·embedding env·slots64·judge workers32다.

```bash
.venv/bin/python experiments/jh_tutor_mlp_compare.py --name tm01_primary
```

`--alternative`는 primary에서 제외된 다른 표현, `--mixed`는 튜터와 가드 혼합을 선택한다. 중단된 채점은 같은 인자에 `--resume`을 더해 재개하며 이미 수집한 응답을 다시 요청하지 않는다. 부분 수집은 별도 이름으로 보존하고 새 실행을 만든다. 실험 결과는 공개 개발 캐시에만 저장하며 배포 요청에는 내용을 기록하지 않는다. API 계측은 별도 개발 부트스트랩이 채팅/임베딩 호출 수와 명시적 진단 boolean만 집계한다.

tm01~tm04의 모든 수집과 채점을 완료했다. 아래에 실행 순서별 결과와 최종 판단을 기록한다.

## 다음 개선 가설

입력 정책 분류기보다 normal/out_of_material 구분과 근거 선택이 더 직접적인 병목 후보로 보인다. tm01 기준선의 action 오류6개 중5개는 abstain→answer였다. 현재 신경망은 마지막 발화만 보고 교재 범위를 판정할 수 없어 이 범주를 기존 경로로 보냈다. 후속은 검색 근거의 실제 답 포함 여부를 확인하거나, 다중 턴 질문을 현재 대상이 명확한 문장으로 해석한 뒤 판정하는 별도 비교가 적합하다. 이는 공개 개발 진단에서 나온 가설이며 비공개 실패 문항을 관찰한 것이 아니다. 이번 라운드에서는 구현하지 않았다.
