## 가설 1: 독립 답변 후보 선택

앞선 영어 지시문 실험은 정상 답변보다 변경하지 않은 정책 응답 점수의 변동이 컸다.
입력과 교재 선택을 고정하여 답변 생성의 기여를 먼저 분리한다.

- `jh_r3_answer_choice`: 정상/PII 학습 답변 3개를 같은 교재에서 독립 생성해 하나를 선택한다.
- `jh_r3_answer_pair`: 2개만 생성하는 비용 절감 대조군.
- 선택기는 현재 질문·자체 선택 교재·답변 후보만 받으며 새 답변을 재작성하지 않는다.
- 같은 답변이거나 시간이 부족하면 선택 호출 생략. 선택 오류면 첫 유효 답변 유지.
- 추가 생성은 8초, 선택은 최대 4초, 기존 요청 전체 26초 마감 안에서 수행한다.
- guard, 입력 분류, 교재 선택, 정책 응답은 기존 그대로다.

`jh_tutor_generation_probe.py`는 로컬 공개/검증된 파생 진단의 자체 응답에서 action=answer와
인용 1개를 가진 문항만 재생성한다. 정답 category/evidence를 생성에 주입하지 않는다.
그 외 문항은 같은 기존 응답을 유지하며 원본 평가기로 전체 tutor를 집계한다.
원래 답변·새 기준선 생성·새 후보 생성을 구분하고 동일 공개 판정 호출만 journal로 재사용한다.
이 진단의 26초는 생성 단계만의 제한이다. 채택 전에는 실제 HTTP/동시 요청 검증이 필요하다.
원본 응답, 실패, 판정은 ignored cache에 보존하고 요약·해시·분석을 이 문서와 JSON에 기록한다.

## 가설 2: 섹션 일치 특징으로 학습한 재정렬

단순 BM25/dense 순위 혼합, 섹션 ID 직접 분류, LLM 섹션 선택과 구분한다.

섹션 ID나 질문 ID는 학습 특징에 넣지 않는다. 원본 119개 질문의 공개 evidence 라벨로만

기존 KB55/KB57은 학습에 넣지 않고 별도 개발 진단으로 측정한다.

## 추가 개발 진단: 주제가 바뀐 대화

단일 질문만 있는 KB57과 공개 부모 변형에만 의존하지 않도록 통제된 대화 진단을 준비한다.
이미 검토한 KB 질문·정답·근거는 유지하고, 다른 섹션의 학습 질문과 실제 교재 인용을 앞 대화로 붙인다.
마지막에는 주제를 바꾼다고 명시하고 원래 질문을 그대로 묻는다. 같은 과목/다른 과목 두 조건이다.

정답 evidence/category는 HTTP에 보내지 않는다. 이전 assistant 발화는 다른 섹션의 실제 교재 문장이다.
원래 질문이 그대로인 스트레스 진단이므로 새 독립 holdout이라고 하지 않는다.
관련 없는 앞 대화에 검색이 끌리는지, 마지막 질문의 대상이 유지되는지를 측정한다.

스트레스 진단이며 실제 제출 분포의 실패율은 아니다. 전체 질문 검색과 마지막 질문 검색을

선택 설정은 공개108/119, 변형109/119를 유지했고 주제 전환4/114→47/114였다.
이 임곗값은 같은 개발 자료를 보고 골랐으므로 OOF/holdout 성능이라 하지 않는다.
`jh_query_gate_screen.py`로 다시 실행해 최초 일회성 그리드와 결과 전체가 일치함을 확인했다.
캐시 `jh_query_gate_r3_screen1`/`screen2`에 모든 조합·자료 해시·문항별 특징을 보존했다.
질의 경량화 두 후보를 새 HTTP 응답으로 비교한다. 마지막 사용량 확인 used14/remaining86%다.

## 가설 5: 전제 확인과 완전한 관련 문장

자체 실패 답변에서 질문에 섞인 다른 예제로 넘어가거나, 올바른 사실의 일부 행동만 남기는 사례를 확인했다.
`jh_r3_checked_answer`는 원래 간결한 답변 지시에 전제 확인·주장 대조·예제 구별만 덧붙인다.
`jh_r3_sentence_answer`는 직접 관련된 교재 문장 한두 개를 온전하게 인용한 뒤 필요할 때만 설명한다.
이전 quotes JSON의 부분 문자열 검증/실패 재생성은 쓰지 않는다. 일반 텍스트 생성 1회다.
둘 다 정상/PII 답변 프롬프트만 바꾸며 입력·근거·guard와 토큰/시간 한도는 같다.
먼저 기존 자체 근거·입력을 고정한 변형192와 KB57에서 새 기준선과 비교한다.
