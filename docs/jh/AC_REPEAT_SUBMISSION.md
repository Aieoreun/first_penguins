# A/C 실제 제출 5회씩 비교

상태: 사용자 보고 A1 수신(1/10회). A 1/5회, C 0/5회. 다음 순서는 C1이다. 기존 단회 제출은 이 묶음의5회에 포함하지 않고 별도 참고 자료로 유지한다.

- A: `jh_cm_char_mlp50`
- C: `jh_np_timeouts`
- 순서: A1 → C1 → A2 → C2 → A3 → C3 → A4 → C4 → A5 → C5.
- 앞 제출 채점이 끝나고 결과를 기록한 후 서버를 Ctrl+C로 종료하고 다음 후보를 시작한다. Application startup complete 확인 후 제출한다.
- 동일 런박스·커밋·환경변수·의존성·embedding env·slots64 유지. 비교 도중 코드 업데이트/튜닝 없이 진행한다. 기존 F/C/D 실행 코드 b776679에 두 후보가 모두 들어 있다.
- 비교 중 별도 API 실험을 함께 실행하지 않는다. 팀의 공유 API 부하는 통제하지 못할 수 있으므로 제출 시각과 특이 사항을 남긴다.
- 실패·낮은 점수도 모두 기록한다. 제출 실패로 점수가 없으면 NA와 사유를 남기고 추가 실행은 별도 번호로 표시한다. 불리한 결과를 조용히 대체하지 않는다.
- 요청/응답 본문은 수집하지 않는다. 집계 결과, 시각, 비내용 오류 종류·개수만 기록한다.

cd ~/first_penguins_jh

## 수신 결과 메모

- A1은 사용자 명시 후보 A(`jh_cm_char_mlp50`)로 기록했다. 제출 시각은 사용자가 KST로 제공한 `2026-11-19T18:09:54`를 그대로 보존했다. 보고일을 제출일로 덮어쓰지 않는다.
- 600요청, 공식 시간 초과·형식 오류/응답 없음·판정 오류 모두0. 서버 내부 오류는 미확인, 특이 사항은 미기재다. 실행 커밋·모델·환경·시작 로그는 아직 확인하지 않았다.
- 기존 A 단회85.41 대비 총점−0.25, 튜터−0.17, 가드−0.32, Duration+0.877초. 이전 결과는 이번 반복5회 통계에 포함하지 않는다. 단회 차이로 회귀나 안정성을 확정하지 않는다.
- 현재 C 결과가 없어 후보 간 평균 차이나 우열을 계산하지 않는다. A1은 최종 보존 후보를 바꾸는 근거가 아니다.
- [기계 판독용 반복 제출 기록](ac_repeat_private_submissions.json). 이번 결과 기록에는 코드 변경·추가 API 호출이 없다.

## 분석 기준

주 판단 지표는 가드 점수이며 총점·튜터·지연도 함께 본다. 후보별 평균·중앙값·표준편차·최저/최고, 오류 수를 계산한다. 인접 A/C 쌍의 차이도 표시하되 서로 다른 seed이므로 같은 문항에 대한 paired test로 취급하지 않는다. 같은 순서의 교대는 장기 시간대 편향을 줄이는 데 도움을 줄 뿐, 순서 효과나 표본 차이를 제거하지 못한다. 5회는 시작 표본이며 우위가 불확실하면 무승부로 유지하고 추가 비교를 검토한다.

최고점만 고르거나 기존 유리한 단회 결과를 이번5회 평균에 섞지 않는다. 같은 계정의 최종 점수는 마지막 제출이며, 이 순서에서는 C5가 마지막이다. 비교 후 보존 후보 선택과 실제 최종 제출은 별도로 판단한다.
