# 문자 TF-IDF + 신경망의 튜터 입력 판정 확장 계획 — 2026-11-19

상태: **사용자 실행 승인 후 로컬 비교 완료.** [결과·최종 판단](TUTOR_MLP_RESULTS.md)을 우선한다. 아래는 실행 전 계획이며 단일 턴 제한 조정 등은 결과 문서에 기록했다. 새 후보의 실제 제출은 아직 없다. 사용자가 임베딩+신경망 제출을 진행하는 동안 요청한 계획이다.

## 현재 보존 기준선

잠정 우선 후보는 `jh_cm_char_mlp50`이다. 직전 명령과 사용자 보고를 대응한 실제 제출은 전체85.41 / 튜터81.25 / 가드89.57 / 69.468초, 공식 오류0, seed `06ac73c87892a4d72c0a10cfa197f8e2`. 현재 공유된 실제 총점 중 최고다. 가드 단독의 역대 최고라는 뜻은 아니며 단회 관측이다.

이 후보는 `/guard`에만 문자 MLP를 적용한다. 튜터는 기존 문자 TF-IDF + LR(C1000, 범주 임계값 .95), 유해 세부유형 판정, 교재 섹션 판정과 LLM 경로를 유지한다. 현재 가드 MLP의 임계값 .8556677733은 OOF 전체400개 중 비유해 예측 상위50%에서 정한 운영점이며, 정확도85.6%를 보장하는 확률이 아니다.

## 목적과 고정할 부분

튜터 입력 오분류를 줄여 answer/scaffold/abstain/refuse/redirect/escalate/clarify 선택을 개선하고, 가능한 경우 분류 LLM 호출을 줄이는 것이 가설이다. 검색·답변 생성·인용의 품질을 분류기 교체만으로 개선한다고 주장하지 않는다.

가드는 현재 char_mlp50의 모델·임계값·보조 LLM·출력 검증을 고정한다. 기존 후보 이름과 동작을 덮어쓰지 않는다. 튜터 모델은 동일하게 학습한 문자 MLP를 읽기 전용으로 재사용하되, 판정 임계값과 활성화 조건은 튜터 전용 설정으로 분리한다. 요청 처리 중 공유 분류기나 공유 임계값을 바꾸지 않는다. 교재 검색·출처 선택·응답 프롬프트·전체 제한시간·주최측 평가기는 고정한다.

## 비교 후보 (이름은 구현 전 임시 이름)

|후보|튜터 입력 경로|확인할 가설|
|---|---|---|
|A: 현재 `jh_cm_char_mlp50`|기존 LR와 LLM 경로 유지|현재 동작 기준선|
|B: `tutor_mlp_selective`|단일 사용자 발화에서 높은 확신의 MLP 판정만 채택, 나머지는 기존 튜터 판정|제한적인 적용으로 오분류를 줄일 수 있는가|
|C: `tutor_mlp_replace`|기존 범주 LR 게이트를 MLP로 교체하고, 불확실하면 공통 LLM 판정|기존 LR의 영향을 제거한 MLP 경로가 더 좋은가|

B에서 MLP가 기권한 뒤 기존 LR이 판정할 수 있다는 점과 C의 불확실 입력이 직접 LLM으로 간다는 점을 명시한다. B/C 비교는 모델 종류 하나의 순수 대조가 아니며 운영 경로 비교다. C도 첫 비교에서는 여러 턴의 대화를 기존 문맥 판정에 맡겨 마지막 발화만으로 의도를 확정하지 않는다. 다중 턴용 특징 추가는 별도 후속 실험이다.

첫 B/C에서는 normal/out_of_material은 MLP만으로 최종 확정하지 않고 기존 교재 판정 경로로 보낸다. 질문 문구만 보는 분류기는 교재에 실제 답이 있는지 검증하지 못하기 때문이다. 더 넓은 범주에 적용하는 실험은 이 비교 결과를 본 뒤 분리한다. 기존 저정보 규칙과 harmful_content의 요청/발언 세부 판정도 유지한다.

현재 `_classify` 호출 체인에는 입력 범주뿐 아니라 섹션 선택 후처리도 있다. MLP 고확신에서 조기 반환해 이 부분을 건너뛰면 검색·인용까지 바뀐다. 구현 시 범주 판정과 섹션 후처리를 분리하거나 명시적으로 연결하고, 후처리가 정확히 한 번 실행되는지 확인한다. 정상·개인정보·정답요구에 대한 기존 출처 경로를 보존한다.

## 실행 순서

1. 공개 자료의 기존 그룹 분할을 고정하고, 튜터 문항에 대한 OOF 범주/action 오류를 진단한다. 학습은 기존 공개400개만 사용하며 같은 원문·유사 질문 그룹이 학습/검증 양쪽에 섞이지 않게 한다. 공개/개발 자료에 이미 노출된 점은 독립 검증 한계로 기록한다.
2. 신경망 출력값을 보정된 확률로 간주하지 않는다. 튜터의 잘못된 거절·주제이탈·교재외 판정, 정답요구/과제대행 혼동, 문맥 의존 질문을 구분해 본다. 상위10/25/50% 직접 처리 운영점을 오프라인 진단하되 실제 전송은 우선 보수적 운영점 하나와 넓은 운영점 하나로 제한한다. 50%는 튜터 실시간 처리율 보장이 아니다. 범주별 표본이 작으면 세밀한 임계값 탐색은 보류한다.
3. A/B/C를 같은 공개 파생 튜터 문항에서 비교한다. 단일 턴과 다중 턴을 나누고, 기존의 원문이 다른 개발 자료에서도 확인한다. 원본 평가기와 판정 프롬프트를 사용한다. 원문 라벨과 기준 답을 결과에 맞춰 변경하지 않는다.
4. 유망한 새 후보 하나와 A를 같은 튜터+가드 혼합 세트에서 순서를 바꿔 반복 비교한다. 튜터 단독뿐 아니라 실제 동시 부하에서 가드 점수·호출량·p95·단계 실패가 악화되는지 확인한다. 동일 가드 구현이어도 실행 점수가 반드시89.57로 고정되는 것은 아니다.
5. 기록에는 튜터 총점/action 오류/답변·인용 지표, 가드 점수, 직접 분류/기권 비율, API 호출, 시간과 오류를 함께 남긴다. 개선이 답변 내용인지 입력 action인지 분리한다. 표본과 반복 수를 같이 표기하고 최고 실행 하나만 골라 비교하지 않는다.
6. 로컬 결과와 단일·다중 턴의 실패 양상을 검토해 실제 제출 시험 후보를 고른다. 이번에 문자 MLP가 로컬 순위와 실제 제출 순위가 달랐던 점을 고려해 로컬 소폭 열세만으로 유망 후보를 모두 폐기하지는 않는다. 원래85.41 후보는 코드·실행 명령과 함께 계속 보존한다.

## 필요한 검증과 결과 해석

- 가드 경로가 그대로인지, 튜터/가드 동시 실행에서 모델·임계값이 섞이지 않는지 확인한다.
- 높은 확신의 판정, 낮은 확신의 기존/LLM 보조 경로, 대화 문맥·유해 세부유형·교재외 경계, 섹션 후처리를 검증한다.
- 튜터 점수가 개선돼도 가드 점수가 무작위 또는 부하 차이로 변할 수 있으므로 전체 점수도 확인한다. 동일 seed의 로컬 반복은 구현 비교에 유용하지만 판정/생성 변동을 제거하지는 않는다.
- 분류 오류가 아닌 교재 검색/답변 근거 부족이 주된 병목이면 입력 분류기만 반복 조정하지 않고 그 근거를 기록한다.
- 비공개 제출 요청·응답은 저장하거나 학습하지 않는다. 사용자에게서 받은 공식 집계와 내용 없는 상태 로그만 기록한다.
- 계정별 마지막 제출이 집계된다. 현재85.41을 재제출 이후에도 자동 보존할 수 있다고 가정하지 않는다. 지금 진행 중인 임베딩 MLP50 제출 결과는 별도 기록하며 이 계획의 기준선을 소급 변경하지 않는다.
