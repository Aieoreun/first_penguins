# 04 실험 기록 — 점수를 잃는 곳 찾기와 고치기 (2026-11-14)

- 한 사람: Claude Code (이승원 요청: "원인 분석 → 가설 → 실험 순서로, 과적합되지 않게")
- 결과물: `pipelines/v3`. v2의 구조에 아래에서 검증한 설정을 고정한 흐름이다.
- **이승원이 아직 확인하지 않았다.** 확정된 결정과 다른 곳이 있다(맨 아래 "정해야 할 것").

## 1. 과적합을 막으려고 한 것

- **문항을 나눴다.** 공개 400문항을 조정용 235개와 확인용 165개로 나눴다(`experiments/split.py`, 문항 ID의 해시로 나눠서 언제 돌려도 같다). 분류 프롬프트에 예시로 들어간 공개 문항 20개는 모두 조정용에 넣었다.
- **조정용만 들여다봤다.** 틀린 문항의 내용을 읽고 원인을 찾은 것은 조정용뿐이다. 확인용은 점수만 봤다.
- **새 예시에 공개 문항을 쓰지 않았다.** 새로 쓴 답변·구절 찾기 프롬프트의 예시는 교재에 없는 가상의 내용(도서부 대출)이다.
- **문항 하나를 맞히려는 수정은 하지 않았다.** 고친 것은 구조(다수결), 합치는 순서, 프롬프트의 일반 원칙이다.
- **여러 번 돌렸다.** 같은 설정도 분류 정확도가 1점쯤, 총점이 1~2점쯤 흔들린다. 한 번 돌린 값으로는 정하지 않았다.

한계: 조정용에서 고른 설정을 확인용으로 본 것이 한 번이라, 확인용 점수도 조금은 낙관적일 수 있다. 로컬 판정 모델(gpt-5-nano)은 실제 채점의 판정 모델과 다르다. 첫 제출에서 로컬 80.2점이 실제로는 71.8점이었다.

## 2. 점수를 어디서 잃는가 (v2, 조정용 235문항, `experiments/eval_full.py`)

기준 점수: 총점 84.47 (튜터 82.23, 가드 86.71).

| 잃는 곳 | 관찰 |
|---|---|
| 입력 분류 | 튜터에서 범주를 맞힌 문항의 평균은 0.926점, 틀린 문항은 0.483점이다. 128문항 중 30개를 틀렸다. 튜터가 잃는 점수의 대부분이 여기다 |
| 문항별 흔들림 | 같은 설정을 세 번 돌리면 400문항 중 308개만 세 번 다 같은 범주가 나온다. 세 번 다 맞은 것은 279개, 한 번이라도 맞은 것은 366개다 |
| 정답만 요구 → 과제 대행 | "문제의 정답만 알려 줘"를 차단 확인이 과제 대행으로 잡는다. 과제 대행이 우선이라 정답 요구 문항이 차단으로 간다 |
| 안전 판정 | 차단된 입력의 후보 답변 11개 중 5개를 "요청에 응하지 않았다"고 잘못 봤다. "네, 친구의 휴대전화 번호를 몰래 알아내는 걸 도와줄게요."도 안전하다고 했다 |
| 근거 없는 구절 | 근거가 있는 후보 답변 18개 중 4개에 구절을 잡았다. 교재의 값에서 따라 나오는 말("한도가 5만 원이므로 6만 원은 이체할 수 없어요")을 근거 없다고 봤다 |
| 답변의 모양 | 아래 표. 로컬 판정 모델은 크게 깎지 않았지만 답변으로서 틀린 것들이다 |

|---|---|---|---|---|---|
| 정상 | 59 | 1 | 16 | 12 | 145자 |

교재 밖 답변 11개는 모두 프롬프트의 지시문을 그대로 적었다. 예: "학생이 물은 것을 짚어서 자료에 나와 있지 않다고 말한다. 교재에 그 질문과 가까운 내용이 있으면 둘째 문장으로 한 줄만 알려 준다." 결정 12-1~12-4(짧게, 해요체, 정답은 말하지 않기)도 지켜지지 않았다. 실제 제출에서 튜터 점수가 로컬보다 14점 낮았던 원인 중 하나로 본다 (추정).

## 4. 검증 (확인용 165문항, 전체 채점)

| 설정 | 총점 | 튜터 | 가드 | 범주 정확도 |
|---|---|---|---|---|
| v2 (실험 전) 1회 | 84.00 | 86.46 | 81.55 | 83.0% |
| v2 (실험 전) 2회 | 83.00 | 82.64 | 83.35 | 80.6% |
| v3 설정 1회 | 87.36 | 86.81 | 87.90 | 88.5% |
| v3 설정 2회 | 85.62 | 86.11 | 85.13 | 85.5% |
| v3 설정 3회 (`PIPELINE=v3`) | 86.37 | 87.15 | 85.58 | 84.8% |

- 평균으로 총점 83.5 → 86.5(+3.0)다. 조정용에서는 84.5 → 89.1(+4.6, 한 번씩)이었다. 확인용에서 오른 폭이 더 작다. 조정용에 맞춰진 몫이 조금 있다는 뜻이다.
- 오른 것은 주로 가드(82.5 → 86.2)와 범주 정확도다. 튜터는 확인용에서 84.6 → 86.7로 조금 올랐다.
- 걸린 시간(v3): 튜터 중앙 8초·최대 17초, 가드 중앙 6.5초·최대 13초. 30초 초과는 없었다.
- 단계 실패가 165문항 중 6~12개 있다. 대부분 교재 확인이 응답을 못 읽었거나 시간을 넘긴 것이다. 실패한 확인은 "교재에 있음"으로 처리된다.

## 5. v3에서 아직 안 고친 것

- **근거 섹션.** 낱말 검색 1위가 91%다. 인용이 틀린 문항은 답변도 엉뚱한 섹션을 보고 쓴다. 조정용에서 범주를 맞히고도 만점이 아닌 튜터 18문항 중 5개가 이것이다.
- **교재 밖 판정.** 조정용에서 교재 밖 19개 중 12~16개만 맞히고, 정상을 교재 밖으로 4~8개 오해한다.
- **정상을 탈옥으로 오해.** 프롬프트 과목이 탈옥 개념을 가르쳐서, 그 개념을 묻는 질문을 탈옥으로 잡는다.
- **구절의 경계.** 정답 구간이 어디서 끝나는지가 문항마다 달라서(서술어를 넣기도 빼기도 한다) 구간 F1이 0.79에서 멈춰 있다.
- **정답 요구 답변이 값을 말한다.** 둘째 판 프롬프트에서도 조정용 2문항 중 1~2개가 정답 사실의 숫자를 말했다. 결정 12-2와 어긋난다. 주최 측 답(정답 사실 채점)에 따라 방향이 정해진다.
- **정상 답변이 아직 길다.** 중앙 157자다. 셋째 문장에 군더더기가 붙는다.
- **호출 수.** v3는 요청당 확인 9번 + 답변 1번이다. 제출 한 번에 6천 번쯤 부른다. 규격 7.1절의 "과한 호출"에 걸리는지는 모른다. 실제 채점에서 동시 요청 64개일 때의 시간도 재지 않았다.

## 6. 이승원이 정해야 할 것

v3는 실험 결과를 담은 흐름이고, 설계 문서의 결정은 바꾸지 않았다. 아래는 확정된 결정과 다르다.

| 결정 | 확정된 내용 | v3 |
|---|---|---|
| 9 | 요청당 모델 호출 두 번 | 확인 9번 + 답변(또는 구절 찾기) 1번 |
| 10 | 차단된 입력의 후보 답변은 모델이 판정 | 규칙으로 "안전하지 않음" |
| 14 | 근거 섹션은 입력 가드가 고름 | 낱말 검색 1위 |
| 2.4절 우선순위 | 과제 대행이 정답만 요구보다 앞 | 정답만 요구가 앞 |
| 리라이터 | (제안) 맨 앞에 둔다 | 쓰지 않는다 |

## 7. 다시 돌리는 법

```
set -a; source .env; set +a
python experiments/eval_full.py --pipeline v3 --split holdout --name 이름     # 전체 채점과 항목별 점수
python experiments/eval_classify.py --pipeline v3 --split dev --name 이름     # 분류만
python experiments/answer_check.py full_v3_holdout_이름                       # 답변의 모양
python experiments/sim_merge.py classify_v2_conf classify_v2_conf2            # 합치는 규칙을 계산으로 비교
```

v2에는 실험용 환경변수가 남아 있다(`V2_VOTES`, `V2_SEEK_FIRST`, `V2_SAFE_RULE`, `V2_PROMPTS`, `V2_ANSWER_EFFORT`, `V2_MATERIAL_INPUT`, `V2_REWRITE`). 기본값은 실험 전의 동작이다.
