# 출력 관찰과 재판정

출력 검토 GPT는 최종 grounded/safe/unsupported 값이나 수정 명령을 반환하지 않는다.
후보 원문 구간, 근거 관계(supported/contradicted/nonfactual/insufficient), 이유, 출처 인용을 반환한다.
안전성은 후보가 수행하는 행동(harmful/benign/uncertain)과 해당 구간을 보고한다.
관계 분류도 모델 판단이므로 사실의 정답 보장이 아니다.

## 감독자 처리

- 후보 구간·인용의 존재와 출처를 검사한다. 유효하지 않으면 해당 범위는 유지한다.
- 모순 관찰 + 기존 grounded=false: 그대로 유지하며 모델을 다시 부르지 않는다.
- 모순 관찰 + 기존 grounded=true: 근거 판정 모델만 한 번 재실행한다.
- 기존 grounded=false의 해제: 기존 unsupported 모든 구간이 지지됨/사실검증 비대상으로 관찰된 경우에만 재판정한다.
- 자료 부족: top8로 한 번 재검색한다. 새 자료가 없거나 예산 부족이면 유지한다. 새 자료를 얻었을 때만 근거 모델을 한 번 재실행한다.
- 안전성 충돌: 안전성 모델만 한 번 재실행한다. 안전하다는 관찰로 해제할 때는 답변 전체 검토를 요구한다.
- 재판정 입력에 원문 구간·관계·인용을 review_feedback 데이터로 제공한다. 시스템 지시나 정답으로 취급하지 않는다.
- 재판정의 JSON·원문 구간·수정 범위를 검사한다. 관찰과 계속 충돌하거나 API/검증/시간 제한에 실패하면 기존 판정을 유지한다.
- 한 범위의 실패는 다른 범위의 성공한 재판정을 취소하지 않는다.

출력 관찰 GPT는 한 번만 호출한다. 이후 근거/안전 모델은 각각 최대 한 번이며, 서로 독립적이면 병렬이다.
재판정 결과를 다시 검토하는 반복은 없다. 공통28초 마감과 호출당12초 제한을 공유한다.
출력 관찰1 + 근거 재판정 최대1 + 안전 재판정 최대1이며 재검색은 최대1이다.
입력 검토의 기존 동작은 변경하지 않았다. 1차 입력/근거/안전 모델과 병렬 구조도 그대로다.
기존 check_grounding/check_safety는 review_feedback이 없는 최초 호출에서 기존 정책·페이로드·모델 설정을 사용한다.
검토 기본값 off는 유지한다. all로 실행하면 이 구조가 적용된다. 실행 중 서버는 재시작해야 코드가 반영된다.

## 검증과 한계

문항ID·라벨·공개 정답별 예외는 서버에 넣지 않는다. 합성 단위 테스트는 서버 데이터가 아니다.
단위 테스트는 일치 시 무호출, 충돌 시 대상만 호출, 부분 근거로 전체 해제 방지, 시간 제한·취소,
재검색 상한, 재판정 실패 시 유지, 입력 격리 및 최초 병렬 실행을 검증한다.
실제API 점검은 고정 공개86개 1차 판정/검색자료를 재생한 단일 실행으로 성능 보장이 아니다.
로컬 전체HTTP·64동시 부하·공식 비공개 채점은 별도로 확인해야 한다.
